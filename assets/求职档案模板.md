# 求职档案（模板）

> 复制本文件到用户求职目录，命名为`求职档案.md`，替换全部`〈〉`占位与示例行。
> 本文件是**唯一状态源**：任何环节开始时先读`## 状态`，结束后更新它。不写回技能目录。

## 1. 基本背景

| 字段 | 值 |
|---|---|
| 姓名 | 〈可选，投递材料需要时再填〉 |
| 专业与学历 | 〈专业 · 本科/硕士/博士 · 在读/已毕业〉 |
| 毕业时间或工作年限 | 〈YYYY.MM 或 N 年〉 |
| 招聘类型 | 校招 / 实习 / 社招 |
| 城市 | 〈现居城市〉 |
| 主要经历概要 | 〈实习、项目、竞赛、论文各一行〉 |

## 2. 偏好与约束

| 字段 | 值 |
|---|---|
| **紧迫度** | `立即（<2周）` / `本季（1–3月）` / `长线（>半年）` |
| 目标城市 | 〈可多个〉 |
| 期望薪资 | 〈区间，或"无特别要求"〉 |
| 是否考虑升学 | 是（考研/保研/申博）/ 否 / 未定 |
| 最看重 | 薪资 / 稳定 / 成长 / 工作强度 / 其他 |
| 明确排除 | 〈方向或条件〉 |

紧迫度只取上述三档，它决定路由：`立即`直接进 ③，不做 ②；`本季`做 ②（只设计 1 个项目）并用 ③ 边投边补；`长线`可走完整 ② 并加积累期安排。

## 3. 状态

### 3.1 全局

| 字段 | 值（严格取枚举） |
|---|---|
| 紧迫度 | 立即（<2周） / 本季（1–3月） / 长线（>半年） |
| 本次接手 | 首次使用 / 继续上次 |
| 全局下一步 | ①方向选择 / ②方向简历 / ③JD定制 / ④面试准备 / ⑤投递复盘 / 无 |
| 更新日期 | YYYY-MM-DD |

### 3.2 方向矩阵

| direction_id | 方向 | 阶段 | 材料状态 | 制作确认 | 规划项目 | 下一步 |
|---|---|---|---|---|---|---|
| d1 | 〈行业-岗位类型〉 | ②已定 | 已提供 | 已确认 | 〈项目名〉 | 有 JD 时进 ③ |

- **阶段**只取：`未开始` / `①调研中` / `①已选` / `②进行中` / `②已定` / `已结束`。阶段只记到 ②；各公司的定制、面试与结果看`投递记录.md`
- **材料状态**只取：`未提供` / `已提供` / `不足`
- **制作确认**只取：`未确认` / `已确认`

### 3.3 投递概况

只记汇总，明细一律写在`投递记录.md`（单一来源，不在此重复逐条记录）：

| 字段 | 值 |
|---|---|
| 已投递数 | 〈N〉 |
| 面试中 | 〈N〉 |
| 待跟进 | 〈公司-岗位，日期〉 |

## 4. 方向结论

每个方向一节，供 ② 直接使用，不要求用户重复叙述：

### d1 〈行业-岗位类型〉

- 目标岗位名称：〈招聘平台上的 2–4 个实际岗位名〉
- 典型要求：〈硬性要求 / 高频技能与关键词 / 常见加分项〉
- 目标城市与公司：〈城市；公司分梯队〉
- 期望薪资区间：〈区间＋依据日期〉
- 主要优势：〈2–3 条〉
- 需补短板：〈2–3 条〉
- 规划项目：〈项目名，见项目设计方案〉
- 建议制作顺序：〈1〉

## 5. 关键日期

只记有固定窗口的事项，注明来源与查询日期；查不到的写“未查到”，不估。

| 事项 | 日期 | 来源与查询日期 |
|---|---|---|
| 〈如：秋招网申开放 / 某公司网申截止 / 笔试 / offer 答复期限〉 | YYYY-MM-DD | 〈来源，YYYY-MM-DD 查〉 |

## 7. 更新记录

- YYYY-MM-DD：〈一句话说明本次做了什么、产出了哪些文件、下一步需要什么〉

## 使用约束

- 每次交付结束时**必须**更新 3.1 的`更新日期`与`全局下一步`、3.2 对应方向的`阶段`；文件有新增或更新时同步第 6 节。
- 不在这份文件里写薪资明细、联系方式、身份证件号码等敏感信息，只记"见投递记录/见简历"。
- 与`career-claim-ledger.json`冲突时，以账本的`已确认`记录为准，并在第 7 节记一条冲突说明。
