# 求职档案（模板）

> 复制本文件到用户求职目录，命名为`求职档案.md`，替换全部`〈〉`占位与示例行。
> 本文件是**唯一状态源**：任何环节开始时先读`## 状态`，结束后更新它。不写回技能目录。

## 1. 基本背景

| 字段 | 值 |
|---|---|
| 姓名 | 〈可选，投递材料需要时再填〉 |
| 专业与学历 | 〈专业 · 本科/硕士/博士 · 在读/已毕业〉 |
| 毕业时间或工作年限 | 〈YYYY.MM 或 N 年〉 |
| 招聘类型 | 校招 / 实习 / 社招 |
| 城市 | 〈现居城市〉 |
| 主要经历概要 | 〈实习、项目、竞赛、论文各一行〉 |

## 2. 偏好与约束

| 字段 | 值 |
|---|---|
| **紧迫度** | `立即（<2周）` / `本季（1–3月）` / `长线（>半年）` |
| 目标城市 | 〈可多个〉 |
| 期望薪资 | 〈区间，或"无特别要求"〉 |
| 是否考虑升学 | 是（考研/保研/申博）/ 否 / 未定 |
| 最看重 | 薪资 / 稳定 / 成长 / 工作强度 / 其他 |
| 明确排除 | 〈方向或条件〉 |

通用简历模板不是`已确认`时，② 与 ③ 都不开始制作简历，先按技能 `references/02-方向简历.md` §3 建立或确认模板。

紧迫度只取上述三档，它决定路由：`立即`直接进 ③，不做 ②；`本季`做 ②（只设计 1 个项目）并用 ③ 边投边补；`长线`可走完整 ② 并加积累期安排。

| 更新日期 | YYYY-MM-DD |

### 3.2 方向矩阵

| direction_id | 方向 | **简称** | 阶段 | 材料状态 | 制作确认 | 规划项目 | 下一步 |
|---|---|---|---|---|---|---|---|
| d1 | 〈行业-岗位类型〉 | 〈如 AI推理部署〉 | ②已定 | 已提供 | 已确认 | 〈项目名〉 | 有 JD 时进 ③ |

**简称**是简历文件名的组成部分（`当前版-<简称>.docx`），登记一次后不再变；同一用户的各方向简称互不重复。

- **阶段**只取：`未开始` / `①调研中` / `①已选` / `JD收集中` / `JD已收集` / `②进行中` / `②已定` / `已结束`。`JD已收集`指该方向 JD 样本达到 08 §2.0 的最低线，或用户同意以不足样本继续。阶段只记到 ②；各公司的定制、面试与结果看`投递\投递记录.md`
- **材料状态**只取：`未提供` / `已提供` / `不足`
- **制作确认**只取：`未确认` / `已确认`

### 3.3 投递概况

| 已投递数 | 〈N〉 |
| 面试中 | 〈N〉 |

### 3.4 跨方向缺口

**多方向并行时才填**（两个及以上方向处于 `①已选` 及之后）。单方向的缺口写在`方向/<方向>/差距分析.md`，不在此重复。

来源：岗位线批量检索后的跨方向交叉统计（细则见技能 `references/08-JD检索与候选池.md` §5）。按 **命中岗位数 ÷ 补齐成本** 排序：

| 排序 | 缺口 | 命中的方向与岗位数 | 补齐成本 | 建议动作 |
|---|---|---|---|---|
| 1 | 〈如：Docker 实操〉 | 〈d1×3、d7×2〉 | 〈1-2 天〉 | 〈具体动作〉 |

**必须同时列出“不建议补”的项及理由**（如成本以月计、本季用不到、方向已冻结），否则用户会把有限时间投进性价比最低的能力：

| 不建议补 | 理由 |
|---|---|
| 〈如：内核/eBPF/开源贡献〉 | 〈如：成本数月，d6 已冻结〉 |

检索日期：YYYY-MM-DD（是否需要增量或重收按 08 §6「使用前复查」判定）

## 使用约束

- 每次交付结束时**必须**更新 3.1 的`更新日期`与`全局下一步`、3.2 对应方向的`阶段`；文件有新增或更新时同步第 6 节；多方向并行且完成一轮岗位线检索时同步 3.4。
- 方向被冻结（如发现疑似 JD 反向撰写、事实无法回溯）时，在 3.2 的`下一步`列写明冻结原因与解冻条件，不静默保留可投状态。
- 不在这份文件里写薪资明细、联系方式、身份证件号码等敏感信息，只记"见投递记录/见简历"。
- 与`career-claim-ledger.json`冲突时，以账本的`已确认`记录为准，并在第 7 节记一条冲突说明。
