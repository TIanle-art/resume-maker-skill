## 1. 什么时候读、对标什么

写或改简历里的实习、项目、科研条目时读本文件：④ 项目设计方案里的“简历成稿”、⑤ 的当前版与目标版、⑥ 的投递简历，都用同一套标准。

**目标版对标的是“同方向最强的那位候选人，把同一段经历做到最好、写到最好之后的样子”。** 不是把原来的句子润色一下，而是先想清楚这段经历做到顶应该包含什么，再把它写出来。三个问题定标杆：

1. JD 样本**天花板层**（校招与社招）的面试官，想在这段经历里看到什么能力证据？
2. 这类工作在行业里做得好的人，通常会做哪些事、拿什么指标说话（评测、对比基线、压测、上线、复现、消融、用户反馈）？
3. 这段经历现在缺的是表达、证据，还是内容本身？对应 §6 的三层升级。

当前版与投递简历用同样的写法标准，但只写到“现在真实达到的程度”；目标版写到“应该达到的程度”。

## 2. 一段经历的骨架

```
<名称>｜<角色或职位>                                   <起止时间>
<一句话定位：做什么、为谁、规模多大>（可选，项目与科研建议写）
- 要点 1（总括：背景、目标与个人职责范围）
- 要点 2–4（核心方法、难点攻关）
- 要点 5（量化结果与对比）
- 要点 6（工程或科研规范、产出与影响；可与上一条合并）
技术栈：<按 JD 高频用词排序>
```

- 篇幅：重点经历 4–6 条，次要经历 2–3 条，每条一到两行；目标版里与方向最对口的两到三段都按重点经历写；
- 顺序：最能证明能力的要点紧跟总括之后，不按时间流水账；
- 名称要具体到看得出做了什么，角色写真实的（负责人／核心开发／独立完成／成员）；
- 版式（是否有定位句、技术栈行的位置）跟随通用简历模板，模板没有的元素先问用户要不要加。

## 3. 写作方法、每条要点的写法与六项检查

### 遵循的写作方法

详细描述不凭感觉写，按下面这些通行方法来。**整段经历用 STAR 搭结构，每条要点用 XYZ 写句子**，其余方法按经历类型选用：

| 方法 | 结构 | 用在哪 | 怎么落到简历上 |
|---|---|---|---|
| **STAR** | 情境 Situation → 任务 Task → 行动 Action → 结果 Result | 整段实习、项目的组织 | S 与 T 写在一句话定位和第一条（背景、目标、个人职责）；A 是中间几条（方法、难点）；R 是结果条。行动占篇幅最多，情境只用一句 |
| **XYZ 句式** | 完成了 X（成果），以 Y 衡量（数字），通过做 Z（方法） | 每一条要点 | 中文里通常写成“通过 Z，使 X 由……提升到……（Y）”，或“动作＋方法＋结果”；每条都要有 Y |
| **PAR／CAR** | 问题或挑战 Problem／Challenge → 行动 Action → 结果 Result | 难点攻关类要点 | 先点出问题现象，再写怎么定位、怎么解决，最后给前后对比 |
| **问题—方法—实验—结果** | 研究问题与现有不足 → 方法 → 实验设计 → 结果与产出 | 科研经历 | 四部分各至少一条；实验要写数据集、基线、指标 |
| **金字塔原则** | 结论先行，再给支撑 | 条目内的排序、个人简介 | 最强的成果放最前；每条先说结果或核心动作，再补细节 |
| **强动词开头** | 每条以说得清贡献的动词起句 | 每一条要点 | 设计、实现、重构、定位并解决、搭建、推导、验证、主导；不用负责、参与、协助 |

**量化的五种写法**（没有“提升了多少”时，换一种也能量化）：

| 写法 | 例子 |
|---|---|
| 对比 | 时延由 3.2 s 降至 1.1 s；准确率较基线提升 2.3 个百分点 |
| 规模 | 支撑 1.2 万篇文档、日均 5 万次请求；代码 8 千行；标注 300 条评测集 |
| 频率与周期 | 每周迭代两版；将月度结账由 7 天缩短到 4 天 |
| 范围 | 覆盖 6 张核心报表、3 条业务链路；被 3 个团队复用 |
| 排名与占比 | 课程设计 1/45；Top 5%；贡献了该版本 40% 的提交 |

修改说明里写明每段经历用的是哪种结构（STAR、问题—方法—实验—结果等）。

### 每条要点的公式

**动作与对象（含规模）＋ 关键方法（体现选型或难点）＋ 结果（量化，带对比基线）**，需要时加一句影响。这就是 XYZ 句式的展开。

每条逐项检查，六项都过才算合格：

| 检查 | 标准 | 不合格的样子 |
|---|---|---|
| 动词 | 用说得清贡献的动词开头：设计、实现、重构、定位并解决、搭建、推导、验证、主导 | 负责、参与、协助、了解、学习了 |
| 对象与规模 | 说清做的是什么、多大：数据量、请求量、用户数、代码规模、样本数、周期 | “某系统”“相关模块”“大量数据” |
| 方法 | 写出具体技术或方法，并让人看出为什么这么选、难在哪 | 只堆名词；或只写“采用先进方法” |
| 结果 | 有数字，且有对比对象（优化前、基线方法、行业常见值） | “效果显著”“大幅提升” |
| 个人贡献 | 看得出是“我”做的哪一部分、做了什么决定 | 团队成果直接当个人成果；分不清谁做的 |
| 用词 | 关键技术词用 JD 的原始写法；一条只讲一件事 | 自造说法；一条里塞三件事 |

再加一问：**读完这一条，面试官会想追问吗？** 不会追问的要点，要么太空，要么太平。

## 4. 一段经历必须覆盖的五类要点

重点经历的几条要点合起来，要让人看到这五样东西（不要求一条对一类）：

1. **背景与职责**：解决什么问题、在什么场景、个人负责的范围；
2. **核心方法**：整体方案或架构，关键选型及理由；
3. **难点攻关**：至少一个真问题——性能瓶颈、数据问题、效果不达标、稳定性、资源限制——以及怎么定位、怎么解决；
4. **量化结果**：核心指标前后对比，或与基线方法对比；
5. **规范与产出**：测试或评测体系、文档、上线或交付、开源、论文、专利、获奖、被采用的范围。

缺哪一类，就回到 §6 判断是表达没写出来、证据没补上，还是事情本身还没做。

## 5. 分类型写法

### 实习与工作

主线是**业务价值**：业务背景与团队目标 → 个人承担的模块 → 方法与难点 → 对业务指标或团队效率的影响。

- 写清所在团队做什么、你的模块在其中的位置；
- 结果尽量落到业务或工程指标：时延、成本、准确率、转化、人效、故障数、交付周期；
- 体现工程素养：评审、测试、灰度、监控、文档、协作对象；
- 涉密内容先脱敏：用相对值、量级或区间，不写内部代号与客户名。

### 基于开源项目的项目

写法同项目，另外守住三点：

- **名称写明来源**：`基于 <开源项目名> 的 <你做的事>`，如“基于 XX 的检索增强问答系统二次开发”；
- **只把自己做的写成个人贡献**：复现与部署、读懂并讲清架构、二次开发的增量（新模块、重构、优化、测试、修复 Issue、提交 PR）。原项目已有的功能可以在定位句里交代“原项目提供了什么”，不写成“我实现了”；
- **至少两条要点是增量**：有方法、有前后对比。只有“部署并跑通”撑不起一个项目条目。

### 项目

主线是**从目标到验证**：要解决的问题与目标 → 架构与关键设计 → 难点与取舍 → 指标与测试 → 交付物。

- 第一条交代目标与规模，让人知道这不是教程复刻；
- 至少一条写方案取舍（对比过哪些方案、为什么选这个）；
- 至少一条写验证方式：测试集、压测、对比实验、真实用户；
- 有可查看的产出就写出来：仓库、演示、文档、报告。

### 科研

主线是**问题到结论**：研究问题与现有方法的不足 → 自己提出或改进的方法 → 实验设计 → 结果 → 产出。

- 写清数据集、基线方法、评价指标；
- 结果写相对基线的提升，并说明是否做了消融或显著性验证；
- 产出按真实状态写：在投、已录用、已发表、专利受理或授权、开源代码；作者排序如实；
- 个人贡献要拆出来：想法、推导、实现、实验、写作各做了哪些。

### 非技术岗

同样的骨架，把“方法”换成专业动作，把“指标”换成业务结果：

- 运营、市场：策略与执行动作 → 触达、转化、留存、增长、成本；
- 产品：问题发现 → 方案与取舍 → 上线结果与用户反馈；
- 财务、法务、咨询、研究：范围与复杂度 → 方法与判断 → 准确性、时效、节约、被采纳情况。

## 6. 三层升级与标注

把一段经历从现状写到顶配，分三层做。**目标版三层都做；当前版与投递简历只做第一层，第二、三层的内容用户确认做到后才进。**

| 层 | 做什么 | 标注 | 举例 |
|---|---|---|---|
| L1 表达升级 | 事实不变，按 §2–§5 重写：补上规模、方法、个人贡献、已有数字，调整顺序 | 不需要标注 | “参与后端开发”改成写清模块、方法和已有的结果 |
| L2 证据补全 | 事情做过，但缺数字或缺验证：写成有数字的完整形态，同时问用户 | 用户给了实际值就直接写；没有的写`【待补充】`；需要重新测的标`【待实测】`并给出怎么测 | 做过缓存优化但没记录时延：写出“时延由 X 降至 Y”的形态，X、Y 待补或待实测 |
| L3 内容升级 | 这段经历要到顶配还应该做、且**现在还能做**的事：补一组对比实验、加一个模块、做一次压测、整理成文章或开源、把课程项目扩成完整系统 | 按做完的样子写，标`【未完成】`／`【进行中】`；涉及新技能标`【计划学习】`；指标标`【待实测】` | 在原项目下新增“搭建评测集并完成与两种基线的对比【未完成】” |

边界只有一条：**靠接下来的行动能变成真的，才可以按最好的样子写；已经定型、行动改变不了的事实不动。**

- 不动的：学校与学历、公司与部门、职位头衔、起止时间、已经发生且无法重做的结果（已发表论文的内容与作者排序、已结束比赛的名次、已离职实习期间的业务数据）；
- 可以升级的：项目的范围与深度、可重新测量的指标、可补做的实验与测试、可整理的产出、要学的技能、尚未结束的实习或科研里接下来要做的事；
- 已结束的实习：不新增“当时没做过的工作”。可以做 L1、L2（凭记录或可查证的数据补数字），以及离职后仍能独立完成的延伸（把其中的方法整理成文章、做一个脱敏的复现项目），延伸写在项目栏或该段经历的最后并标注；
- 每条 L2、L3 内容都进目标版修改说明的行动清单，写清要做什么、怎样算做到。

## 7. 数字怎么定

- 已有实际数字：直接用，并写明口径（什么数据、什么环境、对比的是谁）；
- 做过但没记：先问用户；能重测的标`【待实测】`并写出测法；测不了的用`【待补充】`，不替用户估；
- 规划内容的目标值：来自项目设计方案的指标设计，取“认真做能达到”的水平——参考公开基线、同类开源项目的常见结果与用户的设备条件；宁可保守，不写做不到的数字；
- 每个目标值在项目设计方案或行动清单里要有对应的测量方法与验收标准；
- 没有任何依据时不硬造数字，用规模类事实代替（数据量、接口数、覆盖场景数），或写清验证方式。

## 8. 写完自评：评分表与两个测试

每段重点经历写完后自评，每项 1–5 分：

| 维度 | 5 分的样子 |
|---|---|
| 对口度 | 要点覆盖 JD 高频要求，关键技术词用了 JD 原始写法 |
| 技术或专业深度 | 有方案取舍、有真难点、能撑住两层追问 |
| 量化 | 核心结果有数字、有对比对象、口径清楚 |
| 个人贡献 | 一眼看出“我”做了什么、做了什么决定 |
| 区分度 | 不是教程复刻，有规模、有创新点或有完整闭环 |

**目标版里任何一项低于 4 分都要重写；** 是内容不够而不是写法问题时，回到 §6 加 L2、L3，或回 ④ 调整项目设计。当前版与投递简历受事实限制达不到的，如实写并在修改说明里说明差在哪。

两个测试：

- **“所以呢”测试**：每条要点读完问一句“所以呢？”——答不出对业务、对效果、对能力证明的意义，就改或删；
- **追问测试**：对每条要点设想面试官的两层追问（“为什么这么做”“还有什么方案、差在哪”）。答案应当已经在项目设计方案或用户材料里；目标版中用户现在答不上来的，把“能回答这个问题”写进行动清单。

自评结果写进修改说明：每段经历的五项分数、做了哪几层升级。

## 9. 不能出现的写法

- 空话：效果显著、大幅提升、深入研究、熟练运用、积累了丰富经验；
- 职责罗列：负责某某模块的开发与维护（没有方法、没有结果）；
- 名词堆砌：一条里列六七个技术名词，看不出用它们做了什么；
- 流水账：按时间顺序讲做了哪几步，没有重点；
- 说明书：把架构文档搬进简历，一条三四行；
- 把团队成果、平台能力或 AI 辅助的部分写成个人独立完成；
- 没带标注的规划内容；把目标值写成实测值；
- 为了对齐某条 JD 改动 §6 里“不动”的事实。

## 10. 示例

数字均为示意，实际必须来自用户或项目设计方案。

**项目（技术岗）**

- 现状：`参与了一个 RAG 问答系统的开发，负责检索部分。`
- L1 表达升级（当前版可用）：`独立实现企业文档问答系统的检索模块：基于向量检索与关键词检索的混合召回，支持 1.2 万篇内部文档的问答。`
- 顶配（目标版）：

```
企业知识库问答系统｜独立开发                                  2026.03–2026.06
面向 1.2 万篇内部文档的检索增强问答系统，支持多轮追问与引用溯源
- 设计“混合召回＋重排”两阶段检索：向量检索与 BM25 并行召回后用交叉编码器重排，
  Top-5 命中率由 71% 提升至 89%【待实测】
- 针对长文档切分导致的上下文断裂，对比固定长度、语义切分与父子块三种策略，
  选用父子块方案，答案完整率提升 15 个百分点【待实测】
- 搭建 300 条人工标注的评测集与自动评测流程，覆盖命中率、忠实度、时延三类指标，
  每次改动可回归对比【未完成】
- 通过查询改写缓存与批量推理将 P95 时延由 3.2 s 降至 1.1 s【待实测】；
  完成 50 并发压测并输出性能报告【未完成】
技术栈：Python、FastAPI、Milvus、Elasticsearch、bge 系列模型【计划学习：交叉编码器重排】
```

**实习（已结束）**

- 现状：`在数据组实习，协助完成报表开发和数据清洗。`
- 顶配（目标版）：

```
某互联网公司｜数据开发实习生                                  2025.07–2025.10
- 承担增长团队 6 张核心日报的开发与维护，覆盖注册、留存、转化三条链路
- 重构留存报表的计算逻辑，将全量重算改为按日增量，任务耗时由【待补充】分钟降至【待补充】分钟
- 定位并修复上游埋点重复上报导致的 UV 偏高问题，推动补充去重规则，口径差异由【待补充】降至 1% 以内
- 沉淀数据校验脚本与口径文档，被组内 3 名同事复用
```

说明：实习已结束，只做 L1 与 L2；延伸动作“把增量计算方法整理成脱敏的复现项目”放到项目栏并标`【未完成】`。

**科研**

- 现状：`参与导师课题，做了一些模型改进实验。`
- 顶配（目标版）：

```
小样本文本分类方法研究｜研究生课题，第二作者                    2025.09–至今
- 针对小样本场景下提示学习对模板敏感的问题，提出基于检索增强的动态模板选择方法
```
