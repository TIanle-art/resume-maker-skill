## 1. 输出顺序与通用原则

默认交付可编辑 Word；用户要求时附加自包含 HTML、PDF 或 LaTeX。所有格式必须来自同一份已核实事实基线，**优先让它们由同一份数据文件渲染，而不是各自手工维护**：

```
resume-data.json  ──build-html.mjs──►  HTML（自包含，可编辑）
                  ├─build-docx.py───►  DOCX（默认交付）
                  ├─export-resume-pdf.mjs / browser ──►  PDF
                  └─build-latex-resume.mjs ──►  .tex（可选）
```

两条路径，按用户情况选：

1. **用户提供了可编辑且基本可用的原简历**：复制原文件作为底稿，保留其个人信息区、照片、字体、配色、栏目标题与顺序、身份行、技术栈行、项目符号、间距与页面密度；只做局部结构调整。这条路径不经`resume-data.json`。
2. **没有可用原简历、原文件损坏，或需要批量出多版**：用`resume-data.json`作为唯一事实源，`build-html.mjs`与`build-docx.py`从同一份数据渲染，保证多格式一致、可重建。

- 校招通常一页，社招通常不超过两页；内容不足不强行撑页，内容过多优先删减而非缩小到难读。
- 默认 ATS 友好：文本可选择、标题标准、阅读顺序清楚、无隐藏关键词。
- **只做用户认可的局部结构调整**：例如用户认可“实习与项目分开”时，仅拆分该栏目，其他框架保持原样。岗位匹配需要额外重排、增减栏目或更换视觉结构时，先说明并征得用户确认，不默认扩大修改范围。
- 新增内容导致页数变化时仍继承原样式，优先精简内容，不擅自改套另一套模板。
- 始终修改用户副本，不修改`assets/`中的母版，不将真实个人信息写回技能目录。
- 交付的简历不得残留示例人物、示例链接或虚构照片——用`qa_resume.py`验证，而不是只靠目视。未完成类标注与占位符不拦截，交付时向用户列出即可。

## 2. Word 默认规范

按环境从上到下选第一条可用路径：

1. **`python3 scripts/build-docx.py <resume-data.json> <输出.docx> [--variant <名>]`**：跨平台，仅依赖 python-docx，从同一份事实数据生成单栏 A4 Word。批量出多版、无原简历时用这条；
2. **宿主 DOCX/Word 能力**：用户提供了原简历、需要保留其框架时用这条，在副本上编辑；
3. **`html-to-docx.ps1`**：仅 Windows 且装有桌面版 Word 时可用，把已构建的自包含 HTML 转 Word：

```powershell
powershell -NoProfile -File <技能目录>/scripts/html-to-docx.ps1 <用户输出.html> <用户输出.docx>
```

走第 3 条时注意：

- 输入须为 UTF-8 HTML；先完成 HTML 构建，保留实际使用的相对路径图片与 CSS 资源；
- 脚本只在系统临时目录创建副本，移除脚本与`resume-toolbar`编辑工具栏，不修改原 HTML；
- 输出目录必须已存在，DOCX 不得已存在，也不得写入技能目录；需要更新时另选文件名，避免误覆盖；
- Word 的 HTML 导入不等于浏览器渲染，Flex/Grid、分页、图片定位与字体可能变化；转换后必须按本文件渲染门禁检查，不能仅凭脚本成功就宣称版式一致。

以下默认样式用于`build-docx.py`与"无可用原简历"的情况；已有原框架时，以原文件实际样式为准：

- A4 单栏；页边距上下约 1.5 cm、左右约 1.8 cm；
- 姓名 16–18 pt 加粗居中，联系方式一行居中；
- 小标题 12 pt 加粗并带细分隔线；
- 正文约 10.5 pt，行距 1.15–1.3；
- 每段经历首行左侧为公司／项目与职位，右侧为时间；
- 要点使用标准项目符号，时间倒序；
- 中文使用常见字体，英文与数字使用常见西文字体；
- 默认黑色正文，仅保留一个克制强调色或纯黑；
- 默认不使用照片、图标、表格嵌套、文本框和复杂多栏；
- `【待补充】`、`【待确认】`和未完成类标注使用黄色底纹，方便用户一眼看到。

如果目标公司、行业或用户明确要求照片、双栏或视觉型作品简历，可调整，但仍须检查 ATS、分页与阅读顺序。

## 3. HTML 模板与构建

### 模板选择

简历默认交付 Word，Word 由`build-docx.py`生成固定的单栏样式，**不套用 HTML 模板**。只有用户明确要 HTML 或带设计感的 PDF 时才用到本节的模板。

`assets/templates-html/`下有 4 个壳文件，文件名即`variant-<视觉变体>-<角色示例>.html`，各对应一种真正不同的版式（对照见`assets/模板索引.md`）：

| 场景 | 变体 | 说明 |
|---|---|---|
| 默认、ATS 投递、国企与研究机构、社招 | `variant-black` | 黑白单栏，最保守 |
| 校招、想要一点强调色 | `variant-blue-line` | 单栏，蓝色细线标题 |
| 经历较少、设计与内容类岗位 | `variant-centered` | 姓名与标题居中，留白较多 |
| 外企、英文简历 | `variant-english` | 英文标题样式，日期格式统一 |

`assets/asu-resume/template.html`是另一套 ASu 单栏高密度模板，适合项目与实习很多的技术岗；它带公司 Logo 位，Logo 只在能确认且用户需要时保留，否则改成文字。

`assets/frame/base.css`还支持 sidebar、two-column、timeline、cards 等叠加类。用户明确要这些版式时，复制最接近的壳，只在`<body>`上追加对应的`variant-*`类，不新造一套样式；这类版式对 ATS 不友好，使用前先说明。

用户指定模板时优先遵循，不擅自替换。没有用户真实照片时默认不使用照片，不填入虚构人物；壳文件里的`fictional-resume-photo.png`与示例人物只是版式演示，交付前必须替换或删除（`qa_resume.py`会拦截）。公司 Logo 只有能确认且资源可用时才使用；无法确认就用文字，不拿相似 Logo 替代。

### 构建原则

壳文件只作母版，必须复制到用户输出目录后修改，并通过脚本内联公共 CSS、工具栏与编辑器。不得直接把壳文件当成最终交付。

**数据驱动（推荐，批量或多格式时）**：

```bash
node <技能目录>/scripts/build-html.mjs <resume-data.json> <用户输出.html> --variant <变体名>
```

该脚本按`assets/resume-data.schema.json`读取事实，套用指定变体，输出自包含 HTML（已内联 CSS、工具栏、编辑脚本）。

**手工壳文件（少量、需精细控制版式时）**：

```bash
node <技能目录>/scripts/inline-template.mjs <用户内容壳.html> <用户输出.html>
```

默认 ASu 模板改用 `node <技能目录>/scripts/build-asu-resume.mjs <用户内容壳.html> <用户输出.html>`。

脚本需要 Node.js，无 npm 第三方依赖。若 HTML 使用`icons/`、`logos/`或照片，按输出 HTML 的相对路径复制实际使用的资源；不要使用不存在的本地引用。

可批量检查全部壳模板能否构建：

```bash
node <技能目录>/scripts/inline-template.mjs --all <临时输出目录>
```

ASu 包内一致性自检使用：

```bash
node <技能目录>/scripts/build-asu-resume.mjs --check
```

`assets/asu-resume-template.html`是自检基准。只有维护者确认源模板或公共部件变更后，才显式运行`node <技能目录>/scripts/build-asu-resume.mjs --write-baseline`更新基准；无参数调用不会写入技能目录，普通用户始终使用上面的“用户内容壳＋用户输出”形式。

HTML 交付必须自包含编辑功能，并说明如何在浏览器中编辑、保存和打印。不能把整页截图当作可编辑简历。

## 4. PDF 导出

优先使用宿主 PDF 能力或浏览器打印功能。支持 Node.js 22 及以上与本机 Chrome、Chromium 或 Edge 的环境，也可运行：

```bash
node <技能目录>/scripts/export-resume-pdf.mjs <用户输出.html> --out <用户输出.pdf>
```

浏览器不在常见路径时，通过`--browser <浏览器路径>`或宿主支持的环境变量指定。脚本使用临时浏览器配置，不读取用户 Cookie 或浏览器数据库。

人工导出建议：A4、缩放 100%、开启背景图形、关闭浏览器页眉页脚、纸面边距不破坏模板。导出后检查文本可选择、链接可识别、页数正确，不能用截图拼成 PDF。

## 5. LaTeX 可选输出

只有用户明确要求 LaTeX、`.tex`或 Overleaf 时才附加，不替代默认 Word 或用户要求的 HTML。

可用母版：

- `assets/latex-resume/template.tex`：ASu 单栏；
- `assets/latex-resume/compact.tex`：紧凑单栏；
- `assets/latex-resume/academic.tex`：黑白学术风。

LaTeX 与其他格式消费**同一份**`resume-data.json`（字段见`assets/resume-data.schema.json`与示例`assets/resume-data-template.json`），不单独维护一份数据。替换完所有虚构示例后运行：

```bash
node <技能目录>/scripts/build-latex-resume.mjs <简历数据.json> <用户输出.tex> [母版.tex]
```

脚本统一转义`C++`、`30%`、`snake_case`、`A&B`等字符，不要绕过脚本直接拼接用户内容。照片仅使用用户提供的真实文件，并与`.tex`一同交付。

Overleaf 使用：新建空白项目 → 上传`.tex`和实际图片 → Main document 选择该文件、Compiler 选择 XeLaTeX → Recompile。未实际编译时明确说明只验证了源文件生成，不声称编译通过。

## 6. 事实与版式验收

### 事实门禁

先跑脚本，再人工过一遍脚本管不到的部分：

```bash
python3 scripts/validate_resume_data.py <resume-data.json>   # 结构化事实：必填、枚举、日期顺序、空值
python3 scripts/qa_resume.py <交付文件.docx|.html|.pdf> [--draft]   # 示例文字、虚构照片、日期格式、页数、标注
```

目标简历和用户决定保留标注的稿子加`--draft`运行：标注只作提示，不算失败；不加时标注算失败，用于用户明确要一份“不带任何标注”的稿子。示例文字、虚构照片等其他失败项必须修掉再交付。人工仍需检查：

- 公司、学校、职位、时间、技术栈和成果均来自用户材料或已确认证据；
- 团队成果、个人动作、AI 辅助和平台贡献没有混淆；
- 带`【未完成】`、`【进行中】`、`【待实测】`、`【计划学习】`的内容没有被自行改写成已完成；
- 示例文字、模板虚构信息已清除；仍保留的标注与占位已在回复中列给用户；
- PR、论文、竞赛、证书和开源状态按当前事实表述；
- 时间线无矛盾，链接有效且目的地可识别。

### 渲染门禁

尽可能将 Word 和最终 HTML 渲染为逐页图像或 PDF 后检查：

- A4 尺寸、页边距和页数正确，无多余空白页；
- 无文本溢出、重叠、遮挡、孤立标题或被截断内容；
- 姓名字段、长邮箱、长链接、项目标题和技能标签能自然换行；
- 字体可读，正文通常不小于 9–9.5 pt，不靠极端压缩塞入一页；
- 照片比例正常且确为本人；工具栏、编辑按钮和调试信息在打印时隐藏；
- 表格、项目符号、分栏和阅读顺序正确；
- PDF 无浏览器 URL、日期、页眉页脚和意外背景；
- 公开链接在纸面上仍能识别域名或关键路径，不只有“网站”“CODE”等标签。

页面密度只作诊断：单页正文通常占可用高度约 82%–96%；多页的非末页约 88%–98%。末页过空时优先重排、合并低优先级内容或改回单页，但不得机械追求比例，更不能编造内容填充。

## 7. 宿主能力降级

- **无 python-docx 且无宿主 Word 能力**：交付结构化 Markdown 或自包含 HTML，并说明尚未生成 DOCX；
- **无浏览器自动预览**：给出人工打印检查步骤，明确“未完成自动视觉 QA”；
- **无 PDF 导出环境**（无浏览器、无 LibreOffice）：保留可编辑源文件，指导用户用本机浏览器或 Word 导出；
- **无 LaTeX 编译器**：只交付源文件和 Overleaf 步骤，不声称已编译；
- **无 Node.js**：用`build-docx.py`直接出 Word，或使用宿主文档能力；不能交付未经内联的壳模板；
- **无法渲染逐页检查**：完成文本与结构检查，列出未验收的视觉项目，不声称“已全面检查”。

可用的辅助渲染工具（有则用，无则跳过）：LibreOffice`soffice --headless --convert-to pdf`把 DOCX 转 PDF 供查页数；`pdftotext -layout`抽取 PDF 文本核对分页与截断。

交付说明至少包含：文件格式、页数、模板或母版、资源是否完整、事实状态、已完成的 QA、未完成的人工检查项。
