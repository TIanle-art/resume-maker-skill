## 1. 输出顺序与通用原则

默认交付可编辑 Word；用户要求时附加自包含 HTML、PDF 或 LaTeX。所有格式必须来自同一份已核实事实基线，不能在不同格式中分别改写事实。

- 校招通常一页，社招通常不超过两页；内容不足不强行撑页，内容过多优先删减而非缩小到难读。
- 默认 ATS 友好：文本可选择、标题标准、阅读顺序清楚、无隐藏关键词。
- 用户提供的原简历版式合适时可以沿用；否则使用本规范。
- 始终修改用户副本，不修改`assets/`中的母版，不将真实个人信息写回技能目录。
- 正式投递版不得残留未完成类标注、示例人物、示例链接或虚构照片。

## 2. Word 默认规范

优先使用宿主可用的 DOCX/Word 创建与渲染能力。已有自包含 HTML，且环境为 Windows 并安装桌面版 Microsoft Word 时，也可使用本技能脚本转换：

```powershell
powershell -NoProfile -File <技能目录>/scripts/html-to-docx.ps1 <用户输出.html> <用户输出.docx>
```

- 输入须为 UTF-8 HTML；先完成 HTML 构建，并保留实际使用的相对路径图片和 CSS 资源；
- 脚本只在系统临时目录创建副本，移除脚本和`resume-toolbar`编辑工具栏，不修改原 HTML；
- 输出目录必须已存在，DOCX 不得已存在，也不得写入技能目录；需要更新时另选文件名，避免误覆盖；
- Word 的 HTML 导入不等于浏览器渲染，Flex/Grid、分页、图片定位和字体可能变化。转换后必须按本文件渲染门禁检查，不能仅凭脚本成功就宣称版式一致；
- 无桌面版 Word、COM 启动失败或转换版式不合格时，改用宿主 DOCX 能力或直接生成 Word，不反复覆盖输出。

默认样式：

- A4 单栏；页边距上下约 1.5 cm、左右约 1.8 cm；
- 姓名 16–18 pt 加粗居中，联系方式一行居中；
- 小标题 12 pt 加粗并带细分隔线；
- 正文约 10.5 pt，行距 1.15–1.3；
- 每段经历首行左侧为公司／项目与职位，右侧为时间；
- 要点使用标准项目符号，时间倒序；
- 中文使用常见字体，英文与数字使用常见西文字体；
- 默认黑色正文，仅保留一个克制强调色或纯黑；
- 默认不使用照片、图标、表格嵌套、文本框和复杂多栏；
- 内部草稿中的`【待补充】`、`【待确认】`和未完成标注使用黄色底纹，正式版不得残留。

如果目标公司、行业或用户明确要求照片、双栏或视觉型作品简历，可调整，但仍须检查 ATS、分页与阅读顺序。

## 3. HTML 模板与构建

### 模板选择

`assets/asu-resume/template.html`是默认 ASu 单栏高密度模板；`assets/templates-html/`另有 18 套壳模板。用户指定模板时优先遵循，不擅自替换。

| 场景 | 建议 |
|---|---|
| 技术岗、项目与实习较多 | ASu 单栏高密度或紧凑单栏 |
| 校招、经历较少 | 简洁单页，避免大留白 |
| 社招、经历较多 | 单页优先，必要时双页 |
| 国企、事业单位、研究机构 | 保守黑白、教育与成果优先 |
| 设计、内容、作品集岗位 | 可选视觉型，但保留清楚文字与链接 |
| ATS 投递 | 优先简单单栏，不用复杂侧栏和图标 |

没有用户真实照片时默认不使用照片，不填入虚构人物。公司 Logo 只有能确认且资源可用时才使用；无法确认就用文字，不拿相似 Logo 替代。

### 构建原则

壳文件只作母版，必须复制到用户输出目录后修改，并通过脚本内联公共 CSS、工具栏和编辑器。不得直接把壳文件当成最终交付。

默认 ASu 模板：

```bash
node <技能目录>/scripts/build-asu-resume.mjs <用户内容壳.html> <用户输出.html>
```

其他 HTML 模板：

```bash
node <技能目录>/scripts/inline-template.mjs <用户内容壳.html> <用户输出.html>
```

脚本需要 Node.js，无 npm 第三方依赖。若 HTML 使用`icons/`、`logos/`或照片，按输出 HTML 的相对路径复制实际使用的资源；不要使用不存在的本地引用。

可批量检查 18 套壳模板能否构建：

```bash
node <技能目录>/scripts/inline-template.mjs --all <临时输出目录>
```

HTML 交付必须自包含编辑功能，并说明如何在浏览器中编辑、保存和打印。不能把整页截图当作可编辑简历。

## 4. PDF 导出

优先使用宿主 PDF 能力或浏览器打印功能。支持 Node.js 与本机 Chrome、Chromium 或 Edge 的环境，也可运行：

```bash
node <技能目录>/scripts/export-resume-pdf.mjs <用户输出.html> --out <用户输出.pdf>
```

浏览器不在常见路径时，通过`--browser <浏览器路径>`或宿主支持的环境变量指定。脚本使用临时浏览器配置，不读取用户 Cookie 或浏览器数据库。

人工导出建议：A4、缩放 100%、开启背景图形、关闭浏览器页眉页脚、纸面边距不破坏模板。导出后检查文本可选择、链接可识别、页数正确，不能用截图拼成 PDF。

## 5. LaTeX 可选输出

只有用户明确要求 LaTeX、`.tex`或 Overleaf 时才附加，不替代默认 Word 或用户要求的 HTML。

可用母版：

- `assets/latex-resume/template.tex`：ASu 单栏；
- `assets/latex-resume/compact.tex`：紧凑单栏；
- `assets/latex-resume/academic.tex`：黑白学术风。

将已确认事实整理为 JSON，字段参考`assets/resume-data-template.json`，替换所有虚构示例后运行：

```bash
node <技能目录>/scripts/build-latex-resume.mjs <简历数据.json> <用户输出.tex> [母版.tex]
```

脚本统一转义`C++`、`30%`、`snake_case`、`A&B`等字符，不要绕过脚本直接拼接用户内容。照片仅使用用户提供的真实文件，并与`.tex`一同交付。

Overleaf 使用：新建空白项目 → 上传`.tex`和实际图片 → Main document 选择该文件、Compiler 选择 XeLaTeX → Recompile。未实际编译时明确说明只验证了源文件生成，不声称编译通过。

## 6. 事实与版式验收

### 事实门禁

- 公司、学校、职位、时间、技术栈和成果均来自用户材料或已确认证据；
- 团队成果、个人动作、AI 辅助和平台贡献没有混淆；
- 正式版不含`【未完成】`、`【进行中】`、`【待实测】`、`【计划学习】`；
- `【待补充】`、`【待确认】`、示例文字、模板虚构信息已处理；
- 最终目标简历没有被误作正式投递版；
- PR、论文、竞赛、证书和开源状态按当前事实表述；
- 时间线无矛盾，链接有效且目的地可识别。

### 渲染门禁

尽可能将 Word 和最终 HTML 渲染为逐页图像或 PDF 后检查：

- A4 尺寸、页边距和页数正确，无多余空白页；
- 无文本溢出、重叠、遮挡、孤立标题或被截断内容；
- 姓名字段、长邮箱、长链接、项目标题和技能标签能自然换行；
- 字体可读，正文通常不小于 9–9.5 pt，不靠极端压缩塞入一页；
- 照片比例正常且确为本人；工具栏、编辑按钮和调试信息在打印时隐藏；
- 表格、项目符号、分栏和阅读顺序正确；
- PDF 无浏览器 URL、日期、页眉页脚和意外背景；
- 公开链接在纸面上仍能识别域名或关键路径，不只有“网站”“CODE”等标签。

页面密度只作诊断：单页正文通常占可用高度约 82%–96%；多页的非末页约 88%–98%。末页过空时优先重排、合并低优先级内容或改回单页，但不得机械追求比例，更不能编造内容填充。

## 7. 宿主能力降级

- **无 Word 能力**：交付结构化 Markdown 或自包含 HTML，并说明尚未生成 DOCX；
- **无浏览器自动预览**：给出人工打印检查步骤，明确“未完成自动视觉 QA”；
- **无 PDF 导出环境**：保留可编辑源文件，指导用户用本机浏览器或 Word 导出；
- **无 LaTeX 编译器**：只交付源文件和 Overleaf 步骤，不声称已编译；
- **无 Node.js**：使用宿主文档或 HTML 能力生成，不能交付未经内联的 ASu 壳模板；
- **无法渲染逐页检查**：完成文本与结构检查，列出未验收的视觉项目，不声称“已全面检查”。

交付说明至少包含：文件格式、页数、模板或母版、资源是否完整、事实状态、已完成的 QA、未完成的人工检查项。
