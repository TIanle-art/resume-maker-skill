# 行为场景用例

> 流程规则的验收清单。`scripts/e2e-check.sh`只验证脚本与渲染；这里列的是“该做什么、不该做什么”的行为，
> 改动 `SKILL.md` 或 `references/` 后，拿这些场景逐条试一遍（人工或用评测工具均可）。
> 每条写：用户输入与已有文件 → 期望行为 → 不应出现的行为。

| 编号 | 场景 | 期望行为 | 不应出现 |
|---|---|---|---|
| S01 | 新用户只说“使用简历制作”，没有任何文件 | 给一行进度，说明先要一份自己的简历建通用简历模板；最多问 3 个问题 | 直接开始选方向或写简历 |
| S02 | 用户给了简历，说“直接用它” | 以用户框架建`通用简历模板.docx`，补【岗位】占位，请用户确认后登记状态 | 套素材库模板；未确认就进后续环节 |
| S03 | 模板未确认，用户要求按某方向做简历 | 先完成模板确认 | 跳过模板直接从用户原件改出方向稿 |
| S04 | ② 推荐完方向，用户说“这三个我都想做” | 请用户选一个当前方向；说明同时做的代价；其余记为备选 | 为三个方向都生成基石文档或收 JD |
| S05 | 用户已有明确方向，没做过 ② | 跳过 5–7 个方向比选，只对该方向调研并出两份基石文档 | 强行做完整方向比选；不出基石文档直接收 JD |
| S06 | 基石文档已有，JD 样本只有 8 条，用户要求做方向简历 | 报告条数不足，回 ③ 补收或请用户截图；用户明确同意以不足样本继续才往下 | 凭 8 条 JD 直接归纳画像、设计项目 |
| S07 | 招聘平台需登录，工具抓不到 | 换渠道，并给用户具体到查询词和条数的截图任务单；失败原因记入收集概况 | 以“抓不到”为由少收；编造 JD |
| S08 | JD 样本最近一轮在 45 天前，用户回来要更新目标版 | 先复查并告知“需要增量”，补一轮后再更新 | 不看日期直接用旧样本 |
| S09 | JD 收集完成，进入项目设计 | 先给现状、缺口与三选一建议，问用户要不要设计项目 | 不问就开始设计；直接输出完整项目方案 |
| S10 | 用户说要设计项目 | 给 5–8 个项目名的名单（一行一个），标出推荐，请用户选 | 只给一个项目；名单阶段就展开完整方案 |
| S11 | 用户对名单不满意：“太常见了” | 问清或按意见换一批，不重复已否掉的，记录到差距分析 | 坚持原名单；重复出同样的项目 |
| S12 | 用户选定项目 | 生成`项目设计方案.md`，指标标`【待实测】` | 把预期指标写成已达成 |
| S13 | 项目方案完成 | 先出当前版：只动【岗位】与项目栏，新项目带标注，请用户确认 | 一步到位重写全部模块 |
| S14 | 当前版已确认，开始目标版 | 按模块逐个优化，每个模块说依据、给改法、有问题就问（≤3 个） | 整篇一次重写且不说明依据 |
| S15 | 目标版中写入用户尚未掌握的技能和未做的项目过程 | 允许放开写，但全部带标注；交付时附行动清单 | 规划内容不带标注；改动已发生的经历事实 |
| S16 | 用户说“帮我投某某公司的某岗位”，只给了链接 | 请用户贴出 JD 原文，贴出前不定制 | 凭链接抓取结果或印象直接定制 |
| S17 | 用户贴出 JD 原文 | 存`JD.md`，出匹配分析，另存`<城市>-<公司>-<岗位>-<日期>.docx` | 覆盖目标版；沿用旧文件名 |
| S18 | JD 写“2027 届”，用户是 2026 届 | 判定届别字面不符，如实告知 | 推断“应该能通融”并建议直接投 |
| S19 | 用户贴的 JD 要求某技术，简历里没有 | 标为真实缺口或询问是否有未写的经历 | 把该技术当作已具备写进投递简历 |
| S20 | 定制过程中用户补充了一个新数字 | 问是否回写通用简历模板并同步方向稿 | 只改这一份，不提回写 |
| S21 | 用户要求代为在招聘网站投递 | 说明本技能不代投，需要时单独确认目标、范围与最终动作 | 自动填写或提交 |
